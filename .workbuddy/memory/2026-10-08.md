## 两条新的判据纪律（本轮踩到）

1. **`String(fn)` 会丢掉参数名** —— 想从已加载的函数反查签名会拿到
   `function () { … }`，正则取到的"第一参"是 `function`，一次产出 17 个假阳性。
   要读源码文本。
2. **变异必须能编译** —— `if (peer.protocol === undefined && !peer.countedProtocol)`
   改成 `if (true)` 时 `else if` 变成不可达分支，**tsc 直接红**，判据根本没跑。
   换成"删掉闩锁置位"才测得出真东西。这与 memory 里已有的那条同族。

## 追问：「WS 换 HTTP+SSE 可行吗」深核（同日）

**结论：可行，但不该换。** 理由不是"WS 更好"，而是**我们缺的那个东西
（offset 续传）不需要换传输就能拿到**，而代价落在拓扑里最贵的一侧。
已写进 `V3-PLAN.md` §9.2（原来是"建议只守协议中立性"，现在是带证据的完整论证）。

### 决定性的是拓扑

- WorkBuddy：mp →（HTTP）→ **云端 agent 服务**。客户端发起、服务端流式回 ⇒ SSE 天然贴合。
- 我们：mp ←→ **relay** ←→ host。**host 是长时生产者**，它的上行就是流式输出。
  手机侧 POST+SSE 完美；主机侧要么每帧一个 POST，要么**两条连接模拟全双工**
  —— 而全双工正是 WS 存在的理由。

### ⚠️ 反直觉的核实结果：关闭码语义**没人消费**

`DESIGN.md` §2 的 **T5 写着「客户端的重连策略依赖这些语义」——那句话是假的**：

| 端 | 位置 | 实际 |
|---|---|---|
| 小程序 | `core/socket.js:214` | `t.onClose(() => { this._onClose() })` —— **code 参数被丢弃** |
| 宿主 | `transport/relay.ts:366-370` | `on('close', (code) => { log(...); scheduleReconnect(...) })` —— **只记日志，重连无条件** |

⇒ 「换传输会丢关闭码语义」这个最常见的反对理由**在我们这里不成立**。
已在 T5 行如实标注 + 指向 V3-PLAN §9.2.2。
**教训与 memory 里那条同族**：冻结契约表里的"依赖"也要能指到消费点，否则就是一句
会被下一个人当真的假话。

### 中继的 WS 耦合比预想浅

`state.ts` **只有 5 处**，且早有 `interface Sock { readyState; send(data); close(code,reason) }`
（三成员）—— 状态机本身已经是传输无关的。`server.ts`（1560 行）33 处。
真要做：**新写一个 Sock 适配器 + 重写连接生命周期**，不是重写状态机。

**真正的硬依赖只有三条**：T4 保活（WS 层 ping；小程序**收不到 SSE 注释行**，
还得再加一条显式 keepalive 事件）、`bufferedAmount` 背压（3 处）、`maxPayload`（2 处）。

### 建议（写进计划）

① offset 续传在 WS 上做（它本来就是会话层概念）；
② 要企业代理友好时，在 **relay 边缘加 HTTP 适配器**（`POST /uplink` + `GET /stream?since=N`），
桥到同一条逻辑会话 —— **中继侧的适配层，不是协议变更，主机侧一行不动**。
触发条件：真实用户报"WS 被代理掐掉且改不了"，或要接只能出 HTTP 的客户端形态。

另记三条要实测：`wx.request` chunked 流最大存活时长（WorkBuddy 的 60s 心跳暗示
**不假设流永久**）、chunk 边界不对齐 SSE 行要自己切、换传输**不解决**微信白名单。

## 追问：「要不要把 token 抽成四仓共享的包」深核（同日）

### ⚠️ 这次追问暴露了一个文档缺陷：「token」在本项目里有四种含义

| # | 含义 | 敏感度 |
|---|---|---|
| ① **设计 token**（`--td-*` / `--dsw-alias-*`） | 纯样式 |
| ② `hostToken` / `DRC_HOST_TOKEN` | **中继的出站认证凭据** |
| ③ `pairingToken` | **6 位配对码** |
| ④ `tokenHandle(token)` | **配对码的 sha256 前 8 位**（专为进日志） |

我在 V3-PLAN §12 用了裸词「token」——**在 ②③④ 的语境下「抽成共享包」是一句安全事故**。
已在文首加「名词约定」一节，全文统一成「设计 token」。

### 深核结论：**前提不成立，不抽包**

**① 不是四仓问题。** 实测 6 位色号字面量：协议层 0、中继 0、宿主侧 0
（`qr.ts` / `routes.ts` 都是 0）。**只有两个消费方**：`client/src/pill.ts` 与 `mp/theme/*.wxss`。

**② 两个消费方服务不同的主人 —— 这才是决定性的。**

| 端 | 真相 |
|---|---|
| 插件 pill | `client/src/pill.ts` 全部走 `var(--dsw-alias-*, <fallback>)` —— **宿主的**设计变量。那 7 个色号（`#52c41a`/`#faad14`/`#ff4d4f`/`#5f6368`/`#6b7280`/`#9aa0a6`/`#ffffff`）**全是 fallback**，不是设计系统 |
| 小程序 | `theme/{light,dark}.wxss` 里 **137 个 `--td-*`**（TDesign 命名空间），由 `gen-mp-theme.mjs` 抽取 + 改造成可切换 + `theme:check` 锁同步 |

⇒ **我们一个自己的设计 token 都没有。** 强行统一会让 pill「不像宿主亲生的」——**负收益**。

**③ 共享的是「语义清单」不是「值」**：同一个 `--drc-color-success`，
小程序上是 `#00a885`，插件里是 `var(--dsw-alias-state-success-primary, #52c41a)`。
抽 npm 包只能共享名字 ⇒ 为 4 个语义抽包是过早抽象。
**也不要塞进 `dsh-remote-wire`** —— 那是协议层，塞设计进去会毁掉它的边界。

### 顺手修掉两处自相矛盾

§7 阶段 **F1** 与 §12 **R5** 都还写着「把 token 抽成共享常量」——与新结论冲突，已改。

**文档里的"依赖/共享"必须能指到消费点。** 这次两处矛盾都是同一形状：
写文档时凭直觉推了一条，而代码里根本没有那个消费方。
与 T5 那条同族（`DESIGN.md` 说"客户端依赖关闭码语义"，而两端都不消费）。
