# 2026-10-02 凌晨：真实链路端到端测试 + 清掉真 bug

## 起因

之前的 verify-deployment.mjs 有**自建主机模式**（mock 桥接），拿不到真实配对码时会
静默退化成 mock 并通过 —— 假通过掩盖了真实故障。

## 新建 e2e/live-e2e.mjs（三个真实，绝不退化 mock）
真实小程序代码（mp/utils/drc.js + wx shim）+ 线上中继 wss://drc.provid.cc + 真实内核
（本机 Harness，carrier=services）。拿不到真实配对码直接失败退出。
支持 --rounds / --no-prompt / --session / --pair / --qr；失败时打印事件轨迹。

坑：配对码是**一次性**的，而 status.json 按定时器刷新而非按消费刷新 ——
所以必须只接受**新发布**（age<25s）且本轮没用过的码，否则拿到已消费的码
会以「配对失败」这种假原因失败。

## 它抓出的两个真 bug（都已修）

1. **主机按自己请求的 TTL 记过期**（60s），而服务端实际给 180s。
   码超过 60s 后主机已把 PSK 清扫 → peer-joined 时找不到 PSK → **静默丢弃 peer**
   → 客户端配对成功但之后什么都解不开（列表空 + 「加密解密失败」）。
   修：pair-ready 时以服务端 ttlMs 为准更新过期时间；丢弃时写 relayProblem（status.json 可见）。

2. （前一天修的）多个配对码同时在挂时用错 PSK：pendingPair 单槽 → pendingPairs 按码映射，
   服务端 peer-joined 回传 pairingToken。

## 其他
- mp 聊天页加 disableScroll（与内部 scroll-view 双重滚动会显得「排版乱」）+ cursor-spacing
- pairOnStartSec 暂时保留（方便用户随时取码），文件权限 0600；不需要时删 cordis.patch.yml 那行

## 实测结果
- live-e2e：单轮 10 项、3 轮 24 项，全绿；工具型指令（bash echo）真实跑通；
  归档会话自动恢复后执行成功

## 一个必须先说清的约束：思考正文**不能显示**
`docs/legacy-spec/host-plugin-runtime.md` 的 **M28**（红线，有单测锁着）：

## 三件改动

### ① 归档会话不显示（sessions.js / .wxml / .wxss）
`_renderSessions` 过滤 `state === 'archived'`，同时数出 `hiddenArchived`，
列表底部补一句「已隐藏 N 个归档会话」——**不能悄无声息地少掉**，否则用户以为会话丢了。
空列表时 t-empty 的文案也跟着变（「这里只有归档会话，已隐藏」）。

### ② 点空白收键盘（chat.wxml / chat.js）
根因是两个：小程序 input 拿到焦点后点别处**不会**自动收键盘；
而原来的 `hold-keyboard="{{true}}"` 更是明确要求「点页面不收起键盘」——正好相反。
做法：外层 `.chat-wrap` 挂 `bindtap`（子级 tap 会冒泡上来）→ `inputFocus=false` + `wx.hideKeyboard()`；
输入区与审批/提问面板用 `catchtap="onNoop"` 挡住不误收。
input 的 focus 由 data 驱动（`focus="{{inputFocus}}"` + `bindfocus`），否则失焦是假的。

### ③ chat 页重做为块流（chat.js/wxml/wxss 全量重写）
六种块：`turn`(轮次分隔) / `user`(你的指令) / `think`(思考阶段) / `tool`(工具，可折叠) /
`text`(回复正文，不加气泡、整幅宽读) / `note`(系统提示)。
思考段的开合**不靠事件**（协议没有），靠「任何新块出现就收掉上一段」推断；
还在跑 + 上块已落地 → 插新的一段。于是「思考→工具→思考→工具→回复」的节奏自己就出来了。
顶栏是窗口控制条：状态点 + 运行态 + 展开/收起全部过程 + **中断**（放顶栏而不是输入区，
键盘弹起时输入区会被顶走，而中断恰恰是那时候最想按的）。

## 按需注入 + 用时注入（本次）

**这个特性完全不改包体积**（实测 322.4 → 322.5 KB），所以上传体积数字永远看不出有没有生效，

不许有全局 `usingComponents`（会抵消按需注入）、`componentPlaceholder` 的 key 必须在本页
`usingComponents` 里、值必须是内置组件或已声明组件。做了反向测试（故意删配置 + 写错占位名）
确认能报出 3 个问题并以退出码 1 结束，恢复后复验通过。

`mp-shots.mjs` 现在还会捕获运行时 `exception` / `console.error`（占位替换失败这类错误

## 18:50 前一轮：取历史的「结算点」bug（本轮最贵的一条）

**现象**：`run.mjs` 跑到第 6 步（并发那位新加的取历史步）就**整个卡死**，1 分 40 秒无任何输出，
连 `loadHistory` 自己的 15s 超时都没抛。日志停在那一行不动。

**排查手法（值得复用）**：写最小复现脚本，挂一个 `setInterval` 看门狗每 1s 打一行 ——
**看门狗跟着停 = 事件循环被同步堵死；看门狗在跑而 promise 不结算 = 结算点被吃掉。**
实测看门狗一路跳到 10，所以是后者。（四轮复现脚本在 `/tmp/dbg-history-hang{,2,3,4}.mjs`：
第 2 轮打出「host 只回了 list_sessions 的 `ev.result`、历史那条一条回执都没有」，
第 3 轮打出「内核 `readHistory` 其实**被正常调到了**，参数 `{limit:3}` 正确，
但手机侧 5 秒时 `_historyWaiters` 已被清空却没人结算」。）

**根因**：`loadHistory` 的 `done()` 靠 `if (!self._historyWaiters[cmdId]) return` 做幂等，
所以**谁都不许抢先把登记删掉**。当时两处都抢了：

- `_onEncrypted` 里 `delete` 之后再 `waiter(payload)` → 守卫永远命中；
- `_settleHistory`（断线/解配时）先把表换成空的、再挨个回调 → 同样全部早退。

两条路的后果一样：promise 既不 resolve 也不 reject，**15s 超时也是走 `done()`，一起被吃掉**。
表现：「正在读取主机上的历史…」一直转 /「加载更早」点了没反应，且不发错、不重试。

`_onEncrypted` 那处**并发那位已经修了**（18:46:00）；`_settleHistory` 是我这轮修的
（改成 `Object.keys` 快照后直接回调，让 `done()` 自己删自己那一行）。
