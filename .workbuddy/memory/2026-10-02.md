# 2026-10-02 凌晨：真实链路端到端测试 + 清掉真 bug

## 起因
用户批评：「还是没有端到端的测试，很多都是猜的，实际用一下各种不可用」。
之前的 verify-deployment.mjs 有**自建主机模式**（mock 桥接），拿不到真实配对码时会
静默退化成 mock 并通过 —— 假通过掩盖了真实故障。

## 新建 e2e/live-e2e.mjs（三个真实，绝不退化 mock）
真实小程序代码（mp/utils/drc.js + wx shim）+ 线上中继 wss://drc.provid.cc + 真实内核
（本机 Harness，carrier=services）。拿不到真实配对码直接失败退出。
支持 --rounds / --no-prompt / --session / --pair / --qr；失败时打印事件轨迹。

坑：配对码是**一次性**的，而 status.json 按定时器刷新而非按消费刷新 ——
所以必须只接受**新发布**（age<25s）且本轮没用过的码，否则拿到已消费的码
会以「配对失败」这种假原因失败。

## 它抓出的两个真 bug（都已修）

1. **主机按自己请求的 TTL 记过期**（60s），而服务端实际给 180s。
   码超过 60s 后主机已把 PSK 清扫 → peer-joined 时找不到 PSK → **静默丢弃 peer**
   → 客户端配对成功但之后什么都解不开（列表空 + 「加密解密失败」）。
   修：pair-ready 时以服务端 ttlMs 为准更新过期时间；丢弃时写 relayProblem（status.json 可见）。

2. （前一天修的）多个配对码同时在挂时用错 PSK：pendingPair 单槽 → pendingPairs 按码映射，
   服务端 peer-joined 回传 pairingToken。
