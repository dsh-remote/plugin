# 2026-10-04：Markdown 渲染（mp）

## 调研：没有直接可用的开源方案，四个候选全否

用户要求「找开源项目，不要自己写（覆盖不全）」。实调网络核实：

| 库 | 体积 | 否掉的原因 |
|---|---|---|
| `@ant-design/x-markdown-mini` 1.1.0 | 34.3K gz | 组件是 **`.axml`**（支付宝语法），微信不可用；且输出私有格式，仍要转换层 |
| `mp-html` 的 `parser.js` | 10.6K gz | 输出确实是 nodes，但要配 `marked` 出 HTML 再中转 |
| `marked` v18.0.14 | 14.3K gz | 只出 HTML/toToken，**token→nodes 那层还得自己写** |
| `towxml` / `wemark` / `wxParse` | — | 输出 WXML 结构（非 nodes）；wemark 停更 2023 且**无 License**；wxParse 已死 |

**最终：`marked`（只调 `lexer()`）+ 自写 token→nodes**。语法解析交给成熟实现，
渲染层归我们（因为只有我们知道 rich-text 的限制在哪）。

⚠️ **npm 上没有 `mp-html-parser` 这个包**（实测 404），网上文章全错；
`x-markdown-mini` 官方 `marked.min.js` 是 **ESM**（尾部 `export{}`），小程序 require 直接崩。

## rich-text 的三条硬限制（都实测过）

① **标签白名单**：白名单外的标签被**直接丢掉**（内容凭空消失，界面上看不出原因）→ 只能生成白名单标签 + `prune()` 兜底。
② **不认外部 class**：`attrs.class` 只在自定义组件 wxss 里生效 → 样式全走 inline style，
   **且颜色解析成具体色值**（`var(--x)` 会让深色下字色不变 —— 本项目真机踩过）。
   `check-mp-contrast` 只扫 wxss、看不见 inline style，所以 `PALETTE` 在判据里**自带对比度自证**。
③ **内部不能滚动**：表格必须 `splitTables()` 摘出来由 WXML 侧包 `scroll-view`；
   代码块没法拆（会打乱正文流），改用 `word-break` 折行。
   列宽固定（`COL_W=240`）+ 每格 `word-break:break-all`，「列数×COL_W」才成立。

## 流式：跳变的根因与办法

实测逐字输入 `a **粗体** b`（**不缓冲**时）：
`"a **粗体"`→`"a **粗体"` → `"a **粗体*"`→**`"a *"`**（文字倒退）→ `"a **粗体**"`→`"a 粗体"`。

办法 = `pendingFrom()` 扣住尾部未配对的标记。缓冲后第 7/8 帧内容字都是 `a粗体`，
只是星号消失、加粗补上 —— **文字无倒退**。

### 三个非直觉的坑（都踩过）

① **围栏靠"数配对"必错**：末尾 16 字符窗口**看不到行首那个开始 ```**，两个 ``` 数成 1 次
   → 判成未闭合 → **done 后 pending 还非空**。必须数**行首围栏总数**（`lastLineFence()`）。
   ⚠️ 且不能用 `lastIndexOf` 找"开始的"—— 那会找到**闭合那个**，往后找配对必然失败。
② **围栏的反引号污染行内配对**：闭合围栏的 ``` 被 `` ` `` 数成 3 次（奇数）→ 又判未闭合。
   修法：先切掉围栏那一整行，再数后面的行内标记。
③ **`from = 0` 的歧义**：「不用扣」与「从第 0 字扣起」撞在一起，调用方 `from > 0 ? …` 分不清
   → 流式期第一段一个字都不显示。**用 `-1` 表示"不用扣"**。

### 已知且接受的偏差（别当 bug 重新"修"）

围栏**未闭合**时 marked 会把 `` ```js `` 的 `js` 当语言标记丢掉（`render("```js\nc")`→`"c"`），
代码内容一字不差。

## 这轮最值钱的一条：判据红过 ≠ 判据抓得住

我先写「内容字单调增长」，反证（关掉缓冲）时**它没红**。查下去：
第 7/8 帧内容字都是 `a粗体`（**相同**），真正跳变的是那个 `*`。
补了「标记符号本身也不许中途消失」才在破坏态下真红。

e2e 那 4 条也踩了**破坏没生效**：把 `b.done` 改成 `b.done && !b.done`
（恒 false → 反而**打开**了流式），129 全绿，差点当成"判据无效"。

判据自身还修了三处**不是实现锅**的错：`shown()` 漏算 `split.tables` 的表格、
缓冲区长度用绝对阈值、「纯空白」两条判据自相矛盾。

**判据自身红时，必须逐条查清是判据错还是实现错**，别一律归给实现。

## 反过来的经验：`cd` 在 Bash 工具里不跨调用生效

每次 Bash 调用都是新 shell —— 写 `cd X && python3 …` 时 Python 里的相对路径会
落到别处，报 `FileNotFoundError`（我据此差点以为"破坏没生效"）。
**写文件用绝对路径**，或在同一行里 `cd` 且确认后续命令的工作目录。
