# 2026-10-04：Markdown 渲染（mp）

## 调研：没有直接可用的开源方案，四个候选全否

用户要求「找开源项目，不要自己写（覆盖不全）」。实调网络核实：

| 库 | 体积 | 否掉的原因 |
|---|---|---|
| `@ant-design/x-markdown-mini` 1.1.0 | 34.3K gz | 组件是 **`.axml`**（支付宝语法），微信不可用；且输出私有格式，仍要转换层 |
| `mp-html` 的 `parser.js` | 10.6K gz | 输出确实是 nodes，但要配 `marked` 出 HTML 再中转 |
| `marked` v18.0.14 | 14.3K gz | 只出 HTML/toToken，**token→nodes 那层还得自己写** |
| `towxml` / `wemark` / `wxParse` | — | 输出 WXML 结构（非 nodes）；wemark 停更 2023 且**无 License**；wxParse 已死 |

**最终：`marked`（只调 `lexer()`）+ 自写 token→nodes**。语法解析交给成熟实现，
渲染层归我们（因为只有我们知道 rich-text 的限制在哪）。

⚠️ **npm 上没有 `mp-html-parser` 这个包**（实测 404），网上文章全错；
`x-markdown-mini` 官方 `marked.min.js` 是 **ESM**（尾部 `export{}`），小程序 require 直接崩。

## rich-text 的三条硬限制（都实测过）

① **标签白名单**：白名单外的标签被**直接丢掉**（内容凭空消失，界面上看不出原因）→ 只能生成白名单标签 + `prune()` 兜底。
② **不认外部 class**：`attrs.class` 只在自定义组件 wxss 里生效 → 样式全走 inline style，
   **且颜色解析成具体色值**（`var(--x)` 会让深色下字色不变 —— 本项目真机踩过）。
   `check-mp-contrast` 只扫 wxss、看不见 inline style，所以 `PALETTE` 在判据里**自带对比度自证**。
③ **内部不能滚动**：表格必须 `splitTables()` 摘出来由 WXML 侧包 `scroll-view`；
   代码块没法拆（会打乱正文流），改用 `word-break` 折行。
   列宽固定（`COL_W=240`）+ 每格 `word-break:break-all`，「列数×COL_W」才成立。

## 流式：跳变的根因与办法

实测逐字输入 `a **粗体** b`（**不缓冲**时）：
`"a **粗体"`→`"a **粗体"` → `"a **粗体*"`→**`"a *"`**（文字倒退）→ `"a **粗体**"`→`"a 粗体"`。

办法 = `pendingFrom()` 扣住尾部未配对的标记。缓冲后第 7/8 帧内容字都是 `a粗体`，
只是星号消失、加粗补上 —— **文字无倒退**。

### 三个非直觉的坑（都踩过）

① **围栏靠"数配对"必错**：末尾 16 字符窗口**看不到行首那个开始 ```**，两个 ``` 数成 1 次
   → 判成未闭合 → **done 后 pending 还非空**。必须数**行首围栏总数**（`lastLineFence()`）。
   ⚠️ 且不能用 `lastIndexOf` 找"开始的"—— 那会找到**闭合那个**，往后找配对必然失败。
② **围栏的反引号污染行内配对**：闭合围栏的 ``` 被 `` ` `` 数成 3 次（奇数）→ 又判未闭合。
   修法：先切掉围栏那一整行，再数后面的行内标记。
③ **`from = 0` 的歧义**：「不用扣」与「从第 0 字扣起」撞在一起，调用方 `from > 0 ? …` 分不清
   → 流式期第一段一个字都不显示。**用 `-1` 表示"不用扣"**。

### 已知且接受的偏差（别当 bug 重新"修"）

围栏**未闭合**时 marked 会把 `` ```js `` 的 `js` 当语言标记丢掉（`render("```js\nc")`→`"c"`），
代码内容一字不差。

## 这轮最值钱的一条：判据红过 ≠ 判据抓得住

我先写「内容字单调增长」，反证（关掉缓冲）时**它没红**。查下去：
第 7/8 帧内容字都是 `a粗体`（**相同**），真正跳变的是那个 `*`。
补了「标记符号本身也不许中途消失」才在破坏态下真红。

e2e 那 4 条也踩了**破坏没生效**：把 `b.done` 改成 `b.done && !b.done`
（恒 false → 反而**打开**了流式），129 全绿，差点当成"判据无效"。

判据自身还修了三处**不是实现锅**的错：`shown()` 漏算 `split.tables` 的表格、
缓冲区长度用绝对阈值、「纯空白」两条判据自相矛盾。

**判据自身红时，必须逐条查清是判据错还是实现错**，别一律归给实现。

## 反过来的经验：`cd` 在 Bash 工具里不跨调用生效

每次 Bash 调用都是新 shell —— 写 `cd X && python3 …` 时 Python 里的相对路径会
落到别处，报 `FileNotFoundError`（我据此差点以为"破坏没生效"）。
**写文件用绝对路径**，或在同一行里 `cd` 且确认后续命令的工作目录。

## 根因：`rich-text` 的 `nodes` 不能绑 `wx:for` 作用域里的变量

`nodes="{{item.mdParts[i]}}"` 与 `nodes="{{part}}"`（循环项）都渲染成**高度 0 的空块**。
逐档实测（不是猜的）：

| 绑定 | 结果 |
|---|---|
| `{{topLevelField}}`（纯顶层字段） | ✅ |
| `{{mdMap[item.key]}}`（顶层 map + **一层**索引） | ✅ |
| `{{mdBodies[item.key][pi]}}`（**两层**索引） | ❌ 0 |
| `{{part}}`（`wx:for` 循环项） | ❌ 0 |

**逐个排除的嫌疑**（都别再查一遍）：自闭合标签（`<rich-text/>` vs `</rich-text>`
无差别）、`wx:key="index"`、`wx:else`、wxss（`line-height` 读出来 = 1.65×字号，
说明 wxss 生效了；**同一位置**换字面量 nodes 立刻正常，所以不是样式压成 0）。

## 自举迭代评估（只读代码，未改实现）

完整评估在 `docs/BOOTSTRAP-ASSESSMENT.md`（提交 c89efcb）。三条结论：

**① 重扫的根因是主机自己会自毁，不是协议缺帧。**
`relay.ts:281` 无条件 `generation += 1`，而 `generation` 是**进程内自增计数器**
（`relay.ts:87` 初始化 0），不是中继代次。`closeBefore` 于是每次重连都删掉全部会话
→ `resync` 发空列表 → 中继删 → 手机撞 `unknown_session` → needs-pair。
注释说「中继重启过」，但 `helloOkForHost`（`outbound.ts:51-53`）只回
`{hostId, protocol}`，不带代次 —— **主机无从判断中继是否重启过**。
所以「只有主机重启」被误判成「中继重启」，清空是误伤。

**② 免扫码重连可行，且不需新增协议帧。** 会话拓扑已经 1:1，手机侧 installId 与
convId 都持久化、重启后用同一 clientId 发 hello、中继原样保留，**手机一个字都不用改**。
缺的只是主机重启后还能算出同一份 `kC2H/kH2C` → `ConversationBook` 落盘即可。
安全性没牺牲：`status.json` 现在就已经把有效配对码 + PSK 写在这个目录
（`status.ts:11-12` 注释、`index.ts:386-387` 真返回 `psk`），`host-id` 已是同目录
持久凭据，「中继不可信」由密钥从不上网（D1）保证 —— 落盘在本地，不改变这一点。
⚠️ **必须同时修 generation 语义**，否则落盘回来的会话下次重连又被自己清掉，
症状是「看起来配好了、下一帧就死」，比现在更难查。

**③ appid 自适应配对不可行，建议放弃。** appid 是编译期常量、明文写在
project.config.json；小程序从未调 `getAccountInfoSync`/`login`（全仓 grep 零命中）；
即使去读也是「我自称是 wx…」—— 声明不是证明。
致命点：**知道一个 appid 就能写一个同名小程序**，攻击者不必偷代码。用它放行 =
把门钥匙图案印在门上公开贴出，相对现状是**降低**安全性。
appid 是标识不是凭据，适合的位置是 status.json 审计与多环境命名空间。

**自举还缺的硬阻塞**（除①）：
② **没有可回滚部署路径** —— `install-to-profile.sh:73-77` 是 `rm -rf` + 覆盖，
不备份上一版。①和②叠加就没出路：起不来时手动 checkout，而此时手机已连不上、
人可能不在机器旁。③ 自举必然重启 Harness（脚本自己写明），
在跑的输出与挂起审批都会丢，缺恢复路径。

落地顺序：`hello-ok` 带权威代次 → 修 generation 语义（**必须同一提交**）→
密钥簿落盘（要 `.gitignore` 断言；落盘那部分 TTL 要放宽，否则长假期手机

## 实施：免扫码重连（密钥簿落盘 + 重连不再自毁）

用户拍板范围：**只做重连落盘**，回滚路径与审批续做都不考虑。

### 改了什么

**新增 `packages/plugin/src/shell/pair-store.ts`**：会话簿落盘
`~/.dsh/dsh-remote-control/conversations-<hostId>-<hash8>.json`，0600 + 临时文件 rename。
存的是 **PSK + convId + seqHost/createdAt/lastActivityAt**，不存派生密钥
（派生是纯函数，存结果等于多一份要与 psk 永远相等的第二真相）。
**不存 clientIds** —— 那是"此刻谁连着"，落盘它会让主机一启动就往没人收的通道广播。
读不出（不存在/半写/版本不对/hostId 不符）一律降级成空簿 + 一条日志，**绝不抛**。

**`core/keys.ts`**：加 `restore()` / `snapshot()`；删 `closeBefore()`；
`Conversation.generation` 删掉，改成 `restored?: boolean`。
`PrunePolicy` 加 `restoredIdleTtlMs`（默认 7 天，与中继 `DRC_CONV_IDLE_TTL_MS` 对齐）。

**`transport/relay.ts`**：`hello-ok` **不再清会话**；新增 `restoreConversations()`、
`relayGeneration` getter、`onStructuralChange`（新配对/作废，立刻落盘）与
`onBookActivity`（只动 seqHost/lastActivityAt，只标脏）。
`generation` 自增保留 —— 但语义变成"中继连接代号"，**只喂给 PairingWindow 换码**。

**`shell/config.ts`**：加 `restoredIdleTtlSec`（604800）、`pairStoreFile`
（`''`=自动跟 status.json / `'off'`=关 / 其余=显式路径）+ `resolvePairStoreFile()`。

**`index.ts`**：恢复必须**在 `relay.connect()` 之前**（否则第一帧 resync 声明空列表，
中继当场删掉这些通道）。status 的 3 秒 tick 批量落脏数据；`stop()` 补一次落盘。
status.json 新增 `pairStore{enabled,file,restored,lastSavedAt}`。

### 两个必须记住的坑

**① `runtime.start()` 原来只在 `onPeerJoined` 里**，那假设了"每次有会话可用都伴随一次
新配对"。落盘打破了这个假设：主机重启后手机是**恢复**而非重配，不发
`pair-begin-client`，于是 `onPeerJoined` 永远不来 —— 主机不订阅内核事件、不挂交互 sink、
不起刷新节拍，手机却显示"在线"。**症状与配对丢失在用户眼里完全一样，且 status.json 里
conversations=1、carrier 正常，更难查。** 现在恢复出会话就立刻 `runtime.start()`。

**② 恢复出来的会话不能按 24 小时剪。** 那条 TTL 是给"新配了却没人用"设计的；
恢复出来的那条代表"用户早就配好了、只是主机重启了"。按 24h 剪等于长假之后主机一启动
就把唯一那条通道清了，免扫码重连白做。

### 没改协议（与评估文档 §5 的建议不同，理由记在这）

评估说先给 `hello-ok` 加权威代次。**这一轮没做**：那需要协议仓发 npm 新版本、
plugin 升依赖号才能用上（协议仓已独立、走 tag 触发 GitHub Release）。
而"主机侧分不出中继重启与自己重启"这个前提**在本改动下不成立**：
孤儿会话（有密钥、中继表里已无路由）由既有的「只允许一台」策略回收 ——
新配对时 `onPeerJoined` 会作废除新通道外的全部；手机侧则早已撞 `unknown_session`
→ needs-pair（e2e (b) 锁着）。两边都有出口，不需要额外的权威代次。
**代价**：中继重启后主机会多留孤儿密钥到下一次剪枝（≤7 天），status.json 的
`conversations` 在那段时间偏大。若日后真要做权威代次，落点很干净（generation 那处）。

### 判据与反证

单测 311/311、e2e 全绿。三处反证都确认判据**在缺陷状态下真的会红**：
- 注回 `hello-ok` 里清空会话的两行 → relay-client 的两条 + e2e (c) 同时红；
- 从 `.gitignore` 删掉 `conversations-*` → pair-store 那条红；
- e2e (c) 把 `pairStoreFile` 改 `'off'` → 红在前提断言上。

e2e 的 (c) 判据**整个翻面**（原来断言"必须 needs-pair"，现在断言"必须能续用"），
并新增 (d) 作对照：`pairStoreFile:'off'` 时旧路径原样保留、**不许静默黑洞**。
**这条对照是必需的** —— 否则"关掉落盘时那条路仍然干净"就没人钉着了。

- ESM 包里**没有 `__dirname`**（plugin 是 `"type":"module"`），判据里要用
  `import.meta.url` + `fileURLToPath`；第一版写成 `__dirname` 报的是 ReferenceError，

### 收尾时踩的两个坑（都是"判据/环境骗人"型）

1. **`pnpm -C` 的 cwd 是上一次 `cd` 留下的**：`cd .../packages/plugin && pnpm -C packages/plugin build`
   会变成在 `packages/plugin` 里找 `packages/plugin`，报 `ENOENT … lstat '.../packages/plugin/packages'`。
   **这个 ENOENT 之后紧跟的测试结果是旧 dist 的**，看起来像"破坏没生效"——
   我据此差点得出"反证无效"的结论。反证跑完必须 `grep -c` 确认破坏标记**进了 dist**再看结果。
2. **改 `dist/` 做反证会被下一次 `pnpm test`/`build` 静默覆盖**（`test` 脚本内部先 `pnpm build`）。
   一次我把 dist 恢复后又在错误目录 build 失败，dist 停在半破坏状态，
   e2e 报 `conversation gone` 紧跟 `restored count:1` —— 看起来像"恢复出来的会话被立刻作废"
   的真实现缺陷，插探针才发现根本没有那条日志。**判据指向一个追不到源头的事件时，
   先怀疑产物状态，再怀疑代码。**
3. `controlFrames` 走**进程级**累积的 tap，"配对发生过几次"必须记基线比增量。
   写死 `=== 1` 的那条在 (a) 里侥幸通过（它排第一），(c) 里就以 `3 !== 1` 报红 ——
   而落盘其实完全生效。**判据红时先怀疑判据。**

### 一次假红：并发跑两个 e2e 进程

e2e 全套第一次跑时 (c) 红了一次（`conversations` 0 !== 1，且日志显示恢复后 1ms 内
